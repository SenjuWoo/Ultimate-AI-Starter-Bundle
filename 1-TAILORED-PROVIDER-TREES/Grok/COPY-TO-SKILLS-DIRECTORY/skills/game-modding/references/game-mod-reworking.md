# Repair, modernize, or extend an existing mod

Inventory features, installers, source/generated files, dependencies, optional
integrations, save behavior, config defaults, and known-good hashes before editing.

Explain every removed file, feature, dependency, config key, and package branch.
Do not replace dynamic behavior with a static approximation without approval.
Compare the final version against the parent for feature coverage and package inventory.

Ownership, versioning (Git tags for Git projects; snapshot folders only for snapshot projects) and the never-invent laws: `game-modding` -> `references/MODDING-LAWS.md`.
