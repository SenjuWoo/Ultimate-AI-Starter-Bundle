# v8.7.37 — security and quality flags

## After a push

Required CI checks do not include GitHub's security and quality tab. Code
scanning and code quality can open a finding after the workflow is already
green. `TOOLS/Get-GitHubFlags.ps1` reads one repository and prints allowlisted
fields for open Dependabot, code-scanning, and secret-scanning alerts, plus
code-quality setup and findings.

`flags=clean` means those three alert lists were empty. `flags=unknown` means
a query failed, which is not zero. `flags=open` blocks the tag. A flag on a
file the push changed is fixed and convergence starts over. A flag outside
that push is reported. Alerts are not dismissed. A vendored third-party tree
is not rewritten just to silence a scanner.

A secret-scanning row is the alert number, `secret_type`, and url. The probe
does not print the secret.

## Code quality stays off here

`GET /repos/SenjuWoo/Ultimate-AI-Starter-Bundle/code-quality/setup` returned
404 on 2026-10-07. The probe records that as `code_quality=unavailable`.
That is not an empty finding list. Code Quality spends Actions minutes and
needs a paid plan, so this repository does not turn it on.

Validity checks and non-provider secret patterns are also off. They need
GitHub Secret Protection on an organization plan. The probe reports the
status and does not enable them.

No OSV-Scanner, Gitleaks, or zizmor job was added. Dependabot, code scanning,
secret scanning, and push protection were already enabled.
