# v8.7.18 - RTK installer hotfix

The default `OnlineLatest` installer fetched upstream RTK 0.48.0 even though
the bundle catalog and tested rewrite hook require 0.47.0. It replaced the
installed executable before checking the version, then aborted. Passing
archive-integrity checks alone did not prove version-policy compatibility.

## Fix

- The provider bootstrap now uses Hermes' local `--help` startup check, matching
  the doctor. Its previous `--version` probe could stall on an upstream fetch
  before reaching component installation.
- Installer and component updater share one RTK release selector, using
  `v<catalog version>`. Explicit release tags also protect other components
  whose skills and runtime must stay on the same API.
- Offline/cache fallback requires the shipped manifest's exact SHA-256.
  Core users without an offline RTK asset fetch the same pinned tag.
- Validate the candidate first, stage beside the destination, replace
  atomically, and retain the previous executable as `rtk.exe.bak-uabs-*`.
  A failed post-check rolls back; a locked destination is left intact.

Run `START-HERE.bat` from this version to finish an interrupted installation.
Personal provider configuration continues to follow the existing backup and
ownership rules. No Kimi installation is required for existing four-provider
setups. Windows MCP remains opt-in; the narrow RTK allowlist is unchanged.

## Regression evidence

`TESTS/Test-ReleaseAssetCache.ps1` runs the actual bundled RTK executable on
Windows PowerShell. It tests a newer upstream release, Core without offline
RTK, reused/poisoned archives, verified offline fallback, mismatched tags,
wrong-version rejection before mutation, fresh installation, a locked
destination, preserved backups, and rollback after a failed post-check.
The existing full pack gate runs this test; no compiler or new test dependency
is required. Local installation, CI and downloaded release hashes are checked
separately, rather than inferred from the fixture results.

RTK 0.48.0 has not been adopted or benchmarked by this hotfix. **167 canonical
skills** and all five packaged provider trees remain supported.

## September 13 completion

- Hermes' OpenRouter picker wrapper now patches `model_switch_providers`,
  where current Hermes actually imports it, with a tested old-layout fallback.
  The deprecated alias was scheduled for removal September 14.
- Both updater routes preserve provider selection. An ordinary update now
  delegates to the installer's auto-detection instead of reinstalling all five.
- Playwright CLI 0.1.19 adds a shell-based browser option, no MCP registration
  and no extra skill index entry. Named non-persistent sessions, targeted
  snapshots and explicit session close are documented in tool-discovery.
- CodeBurn 0.9.24, Context7 4.1.0, GitHub MCP 1.12.1 (OAuth metadata scope fix),
  Chrome DevTools MCP 1.9.0 and shadcn 4.21.0 update compatible dependencies.
  GitHub's offline archive is verified against its published SHA-256.
- houseCARL stays on 1.9.0 pending its breaking 2.0 API migration; Impeccable
  stays on the audited engine/skill pair pending its new native engine review.
- Token-efficiency guidance no longer generalizes Anthropic API cache prices
  to every provider, calls schema estimates per-turn bills, or recommends a
  broad RTK rewrite hook. Exact-output commands stay raw.

## September 14 skill routing

- Pack skills now name sibling skills without a `superpowers:` prefix, so Grok
  and other un-namespaced runtimes can load them. The Superpowers plugin copy
  is unchanged.
- Pasted Steam and tools-folder paths are conversation hints, not install
  authority. After a user patches skills and says continue, re-resolve each
  named provider's skill load path, then resume.
- Windows `!` paths are valid on any drive, not only one project root.
- A small Nexus changelog request gets player-facing plain text, not BBCode
  or the internal pack CHANGELOG.
- "Push it to GitHub, code, release, readme" rebuilds the artifact from the
  current source tree. Leftover dist zips from an older SHA are not a release.
