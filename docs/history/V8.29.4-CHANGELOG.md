# v8.29.4 - codebase-memory default registration and current graph

Skill payload: 129 canonical skills, six provider trees.

Codebase-memory was installed but never callable in Hermes. The binary was
present and the graph existed, but `hermes mcp list` had no entry: the installer
aborted the whole Hermes profile migration when a live gateway could not be
stopped, so the native `code` profile never received the server.

- `INSTALL-AIO.ps1` now warns and continues profile migration when the gateway
  has a live session instead of throwing.
- New `TOOLS/Ensure-CodebaseMemoryHermes.ps1` registers the server through the
  supported `hermes mcp add` path, idempotently, and is called by the installer.
  It was tested by removing the entry and re-adding it; `hermes mcp test` then
  reported connected with all 17 tools.
- `list_projects` was pointing at the deleted `-v8.21.0` checkout. Deleted that
  project and indexed the current checkout: 21,372 nodes, 50,000 edges. The
  graph now reports the current root and a real query returns current files.
- Set `auto_watch=false` and `watcher_enabled=false`; indexing is manual. The
  old watcher was trying to watch the user home and being skipped as sensitive.
- New `TOOLS/Start-CodebaseMemory-UI.ps1` starts one keepalive dashboard host
  and is idempotent. `http://127.0.0.1:9749/` returned HTTP 200 and the CBM Lens
  Beta title; the MCP server works without the UI. A Startup shortcut was
  created locally, not shipped.
- Re-measured 0.12.1: 17 tools, 20,814 schema bytes, ~5,204 tokens (bytes/4).
  Updated `codebase-memory`, `capability-profiles`, the catalog scope note, the
  capability record, `docs/TOOL-EVALUATIONS.md` and the release contract.
- Added the local-only project map (`PROFILE.md`, `MACHINE-MAP.md` roots and a
  workspace `WORKSPACE.md`) and pointed `project-intel` at it. Other projects
  are indexed on demand after `.cbmignore` review; no bulk index of unignored
  tool trees or asset folders.
- No new skills; canonical count stays 129.
