## 8.37.24 (2026-11-08)

- Fixes a real integration defect between the two halves of the Ponytail control: the
  auto hook classified prompts without ever reading the selected mode, so with the
  hook wired it could inject LITE/FULL while the operator had chosen OFF. The selected
  mode is now the single authority - `TOOLS/hooks/ponytail_auto.py` reads
  `ponytail-mode/state.json` first and returns nothing unless that mode is `auto`.
  Missing, corrupt or unreadable state means OFF.
- Manual `lite`/`full`/`ultra` stand the hook down instead of adding a competing
  instruction, because the plugin already injects the chosen level.
- `status` in the hook now reports `selected_mode` and `would_inject` rather than
  claiming auto is on; `TOOLS/ponytail_mode.py status` no longer lets "no leaks" stand
  alone - it names the six skills the plugin *registers* (which a model can still
  invoke) separately from automatic injection, so the guarantee is stated for what it
  covers.
- Parking never deletes: an identical duplicate is moved to a `_duplicates` folder
  instead of being removed, which is the behaviour its own docstring promised.
- `TESTS/test_ponytail_integration.py` (9 cases) drives the pair the way a provider
  does: OFF plus a wired hook plus a narrow fix injects nothing; a simplification
  prompt at OFF injects nothing; manual FULL is not doubled by auto; AUTO is the only
  classifier, keeps creative work off, never reaches ULTRA and honours an explicit
  session override; missing and corrupt state inject nothing; a reinstall keeps the
  choice. Wired into CI and the release gate.
- 81 canonical skills, no companion pin changed.
