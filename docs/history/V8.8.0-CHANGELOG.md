# v8.8.0 - Skyrim becomes a pack, Forge moves out, personal profiles

## Skyrim pack (installed only where Skyrim is)

Until this release every user got the Skyrim content: 49 skills (about 2.7k
tokens of skill descriptions in every request), a 24 KB provider instruction
template, Skyrim Forge (213 vendored files), houseCARL and Spooky.

- `BUNDLED-TOOLS/PACKS.json` defines packs. The `skyrim` pack turns on when the
  installer finds evidence on the machine: a Steam app manifest for Skyrim SE/AE
  or VR, `Documents\My Games\Skyrim Special Edition*`, a Vortex `skyrimse`
  folder, a Skyrim/tool environment variable pointing at a real folder, or a
  GOG install. `-Packs skyrim` and `-ExcludePacks skyrim` override detection
  and are remembered in the bundle state folder; detection alone is not
  remembered, so installing Skyrim later turns the pack on by itself.
- A disabled pack installs none of its skills; unmodified copies an earlier
  install left behind are retired by the managed-skill ledger, edited copies
  are kept. houseCARL, Spooky and Forge are skipped (unless named with
  `-Components`), and Hermes' `skyrim` profile follows houseCARL as before.
- Each enabled pack adds one short marked block (`<!-- UABS-PACK:skyrim -->`,
  ~1.6 KB) to every provider instruction file and removes it when disabled.
  An exact copy of an older bundle's long unmarked Skyrim section (ten archived
  versions) is replaced by the provider's new short general template plus the
  block; anything else in the file is the user's and stays.
- Provider-home templates for new installs are now short general files. The
  old Claude/Codex templates also carried a stale "UABS MAX v6.0" preamble that
  duplicated the wired one.
- `game-modding` and `capability-profiles` tell the agent to run
  `START-HERE.bat -Packs skyrim` when Skyrim work starts on a machine without it.

## Skyrim Forge back in its own repository

- Forge 6.0.1 is released from [SenjuWoo/SkyrimForge](https://github.com/SenjuWoo/SkyrimForge)
  (its own CI: Python 3.11/3.13/3.14 on Linux and Windows, native Go writer with
  pinned Go 1.23.2, reproducible repository gate, Windows installer). It carries
  the fixes made while it lived here (PSModulePath isolation in its launchers,
  JSON-escaped path redaction, manifest refresh before validation, the skill's
  player-facing quality gate).
- CATALOG.json pins `v6.0.1`, `Skyrim-Forge-6.0.1.zip` and its SHA-256.
  `Install-SkyrimForge.ps1` takes the Full-Offline copy, a verified earlier
  download, or a fresh download, and refuses any archive whose digest differs
  before extracting. The verified tree is extracted once per digest.
- The release zip's bytes match its own MANIFEST.json (217/217), so the
  same-version hotfix refresh still decides by content.
- CI drops the four Forge jobs (they run in the Forge repository) and keeps
  `forge-bundle-install`: the real installer installs the pinned release,
  `forge doctor` must pass, an upgrade must keep `Workspaces`, and a tampered
  archive must be refused with nothing installed. 14 jobs became 4.
- Dependabot stops watching the removed Go module here.

## Smaller always-on text

- `TOOLS/generate_preamble_history.py` archives every AIO contract, soul and
  provider-template preamble this pack ever shipped (21 texts). Installs strip
  any exact old copy. Measured: one Codex `AGENTS.md` still held the V8.0.1
  contract (12.5 KB) in front of the current one, about 3k extra tokens on
  every Codex request.

## Hermes named profiles

- A Hermes profile clones the default skills folder when it is created and
  nothing refreshed it afterwards. Measured: 26-47 stale bundle skills in each
  managed profile, and about 72 retired skills still indexed in `skyrim`,
  `roblox` and `rimworld`. The installer now refreshes every profile that
  carries the bundle soul (a custom-persona profile such as a role-play gateway
  is left alone), with its own managed-skill ledger. Skyrim pack skills go only
  to `skyrim`; copies in other profiles are moved to a backup, not deleted.
  `Clean-StaleState.ps1` retires renamed/retired skills there too and prunes
  their `SOUL.md` backups.

## Codex MCP pins

- The Codex refresh skipped any table with a policy key and counted
  `enabled = true` (which the Codex app writes itself) as one. Live result:
  Codex launched context7 4.0.4 while Claude, Grok, Hermes and Kimi ran the
  4.3.0 pin. `enabled = true` is no longer policy; a table with real policy
  (`enabled_tools`, approvals, timeouts) keeps it and has only its npm package
  pin moved. Tables are compared by meaning (comments, spacing, literal vs
  basic strings, `enabled = true` ignored), so Codex re-serializing its config
  no longer makes every install rewrite and back it up.

## Personal profile

- `%USERPROFILE%\.uabs\profile\PROFILE.md` (your own preferences) and a
  generated `MACHINE-MAP.md` (Steam game folders, mod-manager staging, My Games
  logs, tool roots, AI app homes, this bundle, the `gh` account) are added as
  one marked, size-capped block (6,000 characters) to every provider
  instruction file. Neither file is in any repository. The installed game list
  goes to `GAMES.md`, read on demand. `-SkipProfile` turns it off,
  `-ProfileRoot` moves it.
- `-ProfileTemplate autonomous-builder` seeds PROFILE.md from
  `BUNDLED-TOOLS/optional-profiles/autonomous-builder.md`, distilled from heavy
  real use: deliver finished work, keep STATE.md for resumption, terse, verify
  current facts, release ritual, payload-only archives, debug logs.

## Measured usage lessons

`TOOLS/usage_report.py` reads local Codex, Claude Code, Hermes and Grok logs and
prints aggregates only. On the maintainer machine (~1,100 sessions):

| Finding | Value |
| --- | --- |
| Median context per Codex tool call in working sessions | ~124k tokens |
| Codex approval-review sessions | 356, ~23% of Codex weight |
| Forked subagent sessions | 95, ~12% of Codex weight |
| Sessions resumed after a usage limit | 71 |
| Folder map retyped by hand | 36 sessions |

These became: `token-efficiency` "where usage goes", `state-resumption`
"usage limits and switching models", `release-checklist` "mod and app sites"
(plain-text changelog, payload-only archive, publish source), the new provider
templates' resume rule, the machine map, and `docs/USAGE-ECONOMY.md`.

## Tests

- New: `TESTS/Test-Packs.ps1`, `TESTS/Test-UserProfile.ps1`; both wired into
  the pack gate with required PASS markers.
- Release contracts now verify the pinned Forge archive (digest, contents,
  version constants, doctor fields, Linux helper mode) and skip Forge internals
  only in Core, which ships no payloads.

## Not changed

- No new always-on MCP; no model or provider setting changed. Codex sandbox and
  approval settings are left to the user (`docs/USAGE-ECONOMY.md` explains the
  trade-off).
- 172 canonical skills remain in the tree; how many install depends on packs.
