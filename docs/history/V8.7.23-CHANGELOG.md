# v8.7.23 - plain-text preamble, one soul per file, ox-alpha retired, eight pins refreshed

**169 canonical skills total**, all five provider trees regenerated. No new dependency, MCP server
or always-on schema.

## The preamble is text, not scaffolding

`INSTALL-AIO.ps1` wires the soul and the operating contract into every provider's instruction file.
Through v8.7 it wrapped that block in HTML comment markers so a later run could find it again. Three
lines of comment went into every provider file, and every request paid for them while they
instructed nothing.

The markers are gone. The block is the tail of the file, and `Install-UabsPreambleBlock`
(`TOOLS\UABS-Common.ps1`) finds where it starts by recognizing the pack's own opening lines - the
soul's first line, the contract's first line, and the two historic forms (the old markers, the
pre-v7.6 soul that opened "You are Hermes Agent"). From that anchor it rewrites to end of file, so:

- re-running replaces instead of stacking (the gate now proves it by running the writer twice);
- a tail that is only the AIO contract, or only the soul, folds into one block;
- a file with operator content above the block keeps that content.

## One soul per file, including every profile

Hermes reads `SOUL.md` from its home, and each named profile carries its own copy. Wiring only the
home copy left four profiles running the older, soul-less form, and left the home plus the creative
profile with the operating contract twice - the duplication reported on the live machine. The
installer now wires the home copy and every existing `profiles\<name>\SOUL.md`, and never invents
one (a profile without a file inherits the home copy).

The live machine was converged with the same writer: ten files (Hermes home + five profiles + four
provider homes) now each hold exactly one soul and one contract, no markers, idempotent on re-run,
with the previous bytes kept as `.before-soul-<timestamp>.bak`.

## stealth/ox-alpha retired

The id is not in OpenRouter's model list any more. It was removed from the portable config (alias
`ox` and the vision fallback chain), from the migrator's alias ladder and from the README. The
migrator gained a retirement sweep: an alias whose value is a retired id, or a vision-chain entry
pointing at one, is planned for removal per profile - exact match only, so an alias pointing at a
live model that merely shares a name stem is untouched. The plan run on the live machine shows the
sweep removing `ox` and `stealth/ox-alpha` from all six profiles while all six keep their
user-chosen fallback chains ("user choice" in the ledger).
