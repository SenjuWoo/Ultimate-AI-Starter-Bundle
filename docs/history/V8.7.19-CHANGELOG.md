# v8.7.19 - Grok hooks and local skill ownership

Grok's independently installed Impeccable hooks used Bash syntax in a
PowerShell host. They ran after edits/writes and at Stop, producing repeated
`At line:1 char:2` errors. The hook installer now migrates only that exact
known command to PowerShell and the `.cmd` launcher, with a byte-preserving
backup. The original project-relative guard remains: unrelated projects do
not start or download the Impeccable engine. Unknown custom commands remain
untouched and invalid native commands are reported by the doctor.

Reviewed local skills can now be explicitly retained in a local-only
`skill-overrides.json` registry. Full-tree hashes prevent unnoticed changes;
missing/changed copies fail verification rather than being overwritten.
The installed-state report counts these separately from exact bundle copies.
No registry or private learning report is shipped in release archives.

The repository moved to **SenjuWoo/Ultimate-AI-Starter-Bundle**. Current
bootstrap URLs, documentation and plugin repository pointers use that owner;
historical changelogs retain their original provenance.

## Verification and scope

The existing Windows PowerShell 5.1 regression gates cover both legacy hook
events, original-byte backup, repeated repair, custom settings, missing
project launcher, and launcher invocation in a spaces/Unicode/`!` path.
Provider sync checks exercise retained overrides, rejected drift/missing
files, and removal of an override to restore bundle ownership.

These are hook/installer tests, not proof of the new Impeccable native
engine's design quality. The bundle retains its audited engine/skill pair;
independently updated local copies are preserved without claiming they are
identical to, or runtime-certified by, the bundle. No additional MCP schema
or always-on server is introduced. Windows MCP remains opt-in; RTK keeps its
measured narrow allowlist. All v8.7.18 skill-routing fixes remain included.
**167 canonical skills** are shipped to all five packaged provider trees.
