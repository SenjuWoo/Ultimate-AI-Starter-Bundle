# v8.10.0 — project intel, security-work contract, personal-data boundary

## Why

Three gaps, each measured before any file was touched (2026-10-12):

- Settled knowledge was re-searched every session. The operator's project
  history already answers hundreds of "what do I do for X" questions, and
  nothing carried those answers to where an agent would look first.
- Technical security work (reverse engineering, cracking, exploit analysis)
  had no explicit authorization in the contract while the NSFW side did, so
  agents still hedged on the technical half. Explicit no-go lines were missing
  too: no malware, no unauthorized targets, verify before alarming.
- The repository is public and had no enforced boundary against personal
  data. A tracked-file scan found two real leaks, both fixed in this release.

## What changed

1. **`project-intel` skill** (canonical tree + all five provider trees):
   a router and six cards — `skyrim-modding`, `skyrim-release`,
   `game-modding-other`, `ai-models-harness`, `apps-native-windows`,
   `security-re`. Sourced from a full scan of the operator's Claude +
   ChatGPT export (318 conversations, 6,188 messages; the 1,433 attachment
   blobs / 10 GB were correctly skipped as non-text) plus the agent-log scans
   that drove 8.9.0. Every line carries a date; the skill's era rule counts
   only frontier-era findings as current evidence (operator cast 2026-10:
   GPT Astral, Sol 6/6.1, Opus 5.5) and forbids shipping model ranking
   tables. Load one card, not all six.
2. **SECURITY WORK clause** in all four AIO variants, both ASCII deployments
   and the workspace copy, sized per variant. Authorization for reverse
   engineering, disassembly, decompilation, memory editing, cracking, keygen
   and exploit development, and DRM/anti-tamper analysis on the user's own
   systems and media; hard lines: never author malware, never target systems
   or accounts without ownership or permission; verify before alarming
   (false-positive procedure with the 2026-09 precedent); never print
   secrets. Every NSFW/jailbreak clause is untouched. The wired-preamble
   digest moved intentionally (`cc9840a5…` → `14daff05…`).
3. **Personal-data boundary**: `SECURITY.md` gains the policy section;
   `.gitignore` gains the blocking patterns; `TESTS/test_privacy_boundary.py`
   scans every tracked file in CI for account names, home paths, personal
   e-mail addresses, locality and forbidden path/name classes. Findings
   fixed during the audit: a third party's e-mail embedded twice in the
   leaked-prompt collection (redacted on the original bytes — CRLF and
   BOM character preserved) and the maintainer's real folder layout in a
   PowerShell test fixture (neutral placeholder paths).
4. **Hygiene**: VERSION/wiki spots bumped (README header + footer,
   START-HERE.txt/bat, INSTALL-AIO banner + state, CATALOG/PROFILES/
   VALIDATION), CHANGELOG section, RETIRED-SKILLS regenerated, provider
   trees re-fanned, preamble history re-archived (23 texts, `--check`
   passes). 173 canonical skills ship in this release.

## Evidence and limits

- `TESTS/test_privacy_boundary.py`: PASS on the full tracked tree.
  `test_release_contract.py`: 143 passed (digest constant updated in this
  same change, as the test demands).
- The intel cards are dated findings, not eternal truth; the era rule and
  the live-verification requirement for model/tool facts are text inside
  the skill itself, not an afterthought.
- Limits: the export's attachment blobs were not analyzed (assets, not
  conversation text). Consumer-chat conversations were sampled by signal
  density, not read end-to-end; the cards say so where it matters.
- Model cast naming (GPT Astral / Sol 6/6.1 / Opus 5.5) is the operator's
  own statement of what they use; it is an environment fact, not a ranking
  or an endorsement.
