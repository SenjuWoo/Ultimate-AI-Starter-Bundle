## 8.19.2

- **Faster installs, measured on a six-app machine.** The Hermes profile migration now reads each profile's config once, through Hermes' own `load_config`, instead of one `hermes config get` process per key (about 4 s each): a plan that changes nothing went from 152 s to 7.6 s with a byte-identical plan. Hermes efficiency defaults are classified in one process instead of 15 CLI calls (65.5 s to 10.2 s). Skill tree fingerprints hash with one reused SHA-256 instead of `Get-FileHash` per file (4.8x faster, identical digests on 321 trees). Skills a native plugin already provides (63 across Claude, Codex and Kimi) are no longer copied in on every run only to be deleted again with a fresh backup; if a plugin is not native at the end of a run, its copies are put back.
- **Fixed: Hermes MCP secrets could be replaced by their mask.** `hermes config get` masks credential-shaped values, and the migration wrote the MCP map it read back whole, so a token in an MCP `env` or `headers` block would have been overwritten with the mask. Reads are now raw, like the writer. (This machine's profiles held no such value; nothing was lost.)
- **Fixed: the live skill sync overwrote skills you preserved on purpose.** `TOOLS/install_live_skills.py` ignored `skill-overrides.json` and, on 2026-10-19, merged the pack's Impeccable 4.1.3 over a preserved 4.3.1 in Claude, Codex and Grok; the next `START-HERE.bat` then stopped at "override changed". The tool now skips preserved skills, and the 4.3.1 copies were restored from that run's backups (digests verified).
- **Fixed: the final check failed installs over an optional tool you installed yourself.** After the REA pin moved to 6.7.0, a hand-installed REA 6.5.0 failed every install with "re-run START-HERE.bat", which cannot fix a tool the bundle never installs. The check now fails only on copies the bundle installed and reports the rest as left alone.
- **Fixed: Spooky's toolkit updated itself on every run.** An external toolkit in a version-named folder (`...-v1.11.2`) kept reporting the old folder version after an in-place update, so each install backed it up and copied it again; it also copied from the archive root instead of the toolkit folder. The update now copies from the `.sln` folder and stamps `.uabs-version`.
- **Fixed: a tool's `--version` probe could hang the installer.** The external-install probe ran the tool with the console's stdin and no limit; it now closes stdin and stops after 10 s. New gate `TESTS/Test-VersionProbes.ps1`.
- **Antigravity plugins stay current.** Superpowers and Ponytail were copied once and never refreshed; they now update every run (copy-only, nothing deleted). `config.json` is rewritten only when a plugin entry actually changes, with a backup, and an existing entry without `enabled` no longer throws.
- **blender-mcp 2.2.2** (released 2026-10-20): Windows initialize/tools-list PASS, 9 tools, 15,754 schema bytes.
- **173 canonical skills total** across all six provider trees; 150 release contract tests pass.
