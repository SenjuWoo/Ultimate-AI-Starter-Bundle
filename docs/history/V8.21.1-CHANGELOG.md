# v8.21.1 - fresh Windows provider setup

- Repair fresh Windows provider discovery, including desktop apps, native/npm
  CLI paths and stale process PATH. Require explicit selection when no app is
  found; never silently install every provider. Deduplicate provider names.
- Bootstrap a missing Codex CLI through OpenAI's documented npm package; share
  executable discovery with the installed-state doctor.
- Seed only missing workspace templates and preview stale-state cleanup by
  default, preserving personal project files, backups and skills.
- Keep vendor permission prompts in fresh Grok starter settings. Existing
  permission and model choices remain user-owned.
- Add Windows regression coverage for provider subsets, missing-provider
  bootstrap and workspace preservation. See docs/WINDOWS-RECOVERY.md.
- Recognize hook commands that still point at the pre-rename hooks folder and
  replace them on upgrade. The retired folder name stays in the shared helper.
- Write the Core archive's README-CORE note once. A tracked copy of that note
  was also packed, so the release check rejected the zip.
- Prove Codex MCP servers with the shared CLI resolver. `Get-Command codex`
  misses a CLI that is installed outside the current process PATH.
- Accept Git Bash when the WSL launcher is the first `bash.exe`. Windows
  searches the machine PATH first, so that launcher always wins a first-match
  check and the doctor failed a working install. Hook dispatchers skip it.
- Configure Hermes shell init and hook wiring with Hermes's own YAML loader.
  Current Hermes builds ship ruamel as `hermes_yaml` and do not install PyYAML,
  so `import yaml` aborted setup wherever Hermes was installed. A child Python
  failure is now copied into `INSTALL-FAILED.txt` and the details log.
  Round-trip saves drop the source carriage return before loading and write
  one newline style. Keeping that carriage return and writing the dump in text
  mode turned each preserved break into a blank line.
