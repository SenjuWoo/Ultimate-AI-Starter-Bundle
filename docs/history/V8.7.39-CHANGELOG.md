# v8.7.39 - review of the search, wait and GitHub-alert changes

Retains v8.7.36-38's canonical-only default search, full-file provider fanout
checks, stable preamble contract and post-push GitHub alert checks.

## Root-cause fixes

- Repair the vendored Forge manifest for six repository-link edits. Its existing
  delivered-tree regression caught the stale hashes on `main`; both release
  variants now carry the matching integrity evidence.
- `Get-GitHubFlags.ps1` no longer treats an empty successful alert response or
  unknown code-quality setup state as clean. Invalid JSON is caught without
  echoing a payload that might contain secret material. Alert arrays must carry
  alert numbers. Code-quality 403/404 remains explicitly unavailable, not zero.
- Validate owner/repository input before constructing native arguments. Drain
  stdout and stderr concurrently; a saturated stderr pipe cannot deadlock the
  probe. Each request has a 60-second timeout, configurable with
  `-TimeoutSeconds`. Unknown/failed security queries still return nonzero.
- `Wait-External.ps1` retains the .NET process handle before waiting and uses
  the signed native exit code. Valid exit 259 and negative Windows failure
  codes are not mistaken for an unfinished process or a conversion error.
  Remove redundant Win32 interop; read the requested UTF-8 log tail directly.
- A 429 is not necessarily daily free-quota exhaustion. Distinguish daily
  exhaustion from transient rate/capacity limits; honor reset/Retry-After
  evidence with bounded backoff. Preserve main/auxiliary model choices.
- Release-contract failures now escape unsupported console characters rather
  than crashing while trying to report a Unicode path; an ASCII-console
  failure-injection check proves the original failure still exits nonzero.

## Verification

The local fake-gh gate exercises actual child-process behavior, including open
alerts, unknown/unavailable quality, missing/malformed/null responses, a full
stderr pipe, timeout, and invalid repository input. No live network or actual
secret is needed by this gate. Windows wait regressions cover 0, 3, 259 and -1.
Both gates remain part of `Test-Pack.ps1`, including extracted release checks.

172 canonical skills. No new MCP server, dependency or always-on schema.
Actual cached/billed-token savings, editor/gameplay and GPU behavior are not
certified by these structural and process tests.
