# v8.7.21 - creative profile, Blender pin refresh, CI pin parity

**167 canonical skills**; no new dependency, always-on server or canon change.

The pack now normalizes a fifth Hermes profile. `creative` clones the user's
default (models, reasoning, compression and fallback chain preserved) and adds
two uvx-served stdio MCP servers on top of the core three:

- `blender` - `mcp-for-blender@2.0.0` (the renamed `ahujasid/blender-mcp`),
  pinned from the catalog, telemetry disabled, safe mode on, loopback host.
- `unity` - the official CoplayDev server, `mcpforunityserver@10.2.0` run in
  stdio mode. This is a different project from the retired IvanMurzak
  `gamedev-mcp-server` lineage; the catalog entry for that other lineage is
  unchanged and separate.

Measured live on 2026-09-17 with the bundle's own handshake probe, no editor
open: Blender answers initialize/tools-list with 31 tools / 35,646 schema
bytes (~8,912 tokens at bytes/4); Unity with 47 tools / 108,248 schema bytes
(~27,062 tokens). These are schema-size estimates, not a bill. Only a tool
call that reaches an open editor proves the editor half; enabling the Blender
addon and opening Unity remain in-editor user steps.

The Unity editor side ships per project: the Woo VRChat project took the
package from the pinned v10.2.0 tag commit `30d2207`, verified
manifest == lock == PackageCache == tag target, and both package assemblies
compiled in a batch import with zero C# errors. The installer does not guess
project paths; users install the package in each project they want wired
(Window > Package Manager > Add package from git URL, then pin the tag).

## CI pinning

The three pack-gate jobs now reference `actions/checkout` and
`actions/setup-python` by the same full commit SHAs the Forge jobs already
pinned, with `persist-credentials: false` on every checkout. Mutable `@v7`
tags in a repo whose whole point is byte-identity were the last floating
references in the workflow.
