# v8.11.0 — codebase-memory lifecycle: purge, rework, and one-shot reindex

## Why

The codebase-memory setup on this machine had drifted in three ways, each
observed before any edit (2026-10-12):

- **Ignore files were snapshot-only, and a re-run reset them.** The setup tool
  rewrote every `.cbmignore` from its template; any hand-added rule (vendored
  `zAssets/`, audit dep trees, a single enormous JSON) was lost. One project's
  graph had silently grown to 90,546 nodes (549k edges) behind a 426 MB db
  because two vendored trees (whole numpy + pandas sources, vendored mods) were
  no longer ignored.
- **No orchestration.** Writing ignores and indexing were separate manual
  steps; nothing produced a per-project verification table, and nothing made
  "index everything in scope" a single safe command.
- **Purge knowledge was scattered and one deletion pass was over-eager.** Five
  projects that the operator's own registry marks as intentionally indexed were
  deleted as "tool trees" before the registry was consulted, and had to be
  restored the same day. The rules needed to be anchored to the registry in the
  skill text itself.

## What changed

1. **`TOOLS/Setup-CodebaseMemory-Index.ps1`** gains the full lifecycle:
   - `-Index`: after applying ignores, indexes every project in scope with the
     server CLI, prints `nodes/edges/excluded/secs/status` per project, exits
     with the failure count.
   - `-ExtraIgnore 'a/','b.json'`: project-specific rules that persist.
   - **Custom-rule preservation**: lines not belonging to the generated base or
     snapshot block survive every re-run, kept under a
     `# --- custom rules ...` header. Idempotency and preservation were proven
     with canary diffs across repeated runs.
   - Base rules extended: `bin/`, `Bin/`, `src/SKSE/`, `SKSEMenuFramework.h`,
     `zAssets/`, `zOlder/`.
2. **`codebase-memory` skill**: documents the server's v0.11.0 `cli` mode
   (one-shot `list_projects` / `delete_project` / `index_repository` from the
   terminal — no MCP client), the registry-anchored purge discipline (source
   trees the operator works on are indexed; only vanished roots, personal
   export folders, and unmodified third-party installs are purged), and
   per-provider auto-routing via `Set-McpProfile -Task code` (project-scoped on
   Claude/Grok/Codex, native `code` profile on Hermes, global opt-in on Kimi).
3. **The index store itself was reworked**: 3 stale entries purged (an indexed
   chat-export folder, two vanished roots), 5 over-purged projects restored,
   all 45 projects re-indexed under the new ignores, and a whole-store outlier
   sweep (top file path per db) reports clean. Final: 45 projects, 63,544
   nodes, store ~357 MB. The operator's registry doc
   (`_AI-SHARED-MEMORY/locations/CODEBASE-MEMORY-PROJECTS.md`) was refreshed
   with the purge record, the rebuilt counts, and the new maintenance commands.

## Evidence and limits

- Tool behavior proven by execution: canary diffs (same file after two runs),
  a single-project `-Apply -Index` end-to-end run, and a 41-project batch
  reindex whose before/after counts are recorded in the registry (worst:
  90,546 -> 2,852 nodes; another 24,530 -> 10,240 after excluding one JSON).
- Limits: node counts are parser-dependent (Papyrus is not parsed by this
  server; `scripts/` is skipped by its built-in list); the outlier sweep flags
  by top-file path, it is a heuristic, not a proof. The registry records both.
- This release changes one tool and one skill; no preamble, contract, or
  provider-wiring text was touched. 173 canonical skills total.
