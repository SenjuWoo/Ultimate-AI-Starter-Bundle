# v8.7.22 - workspace and scratch skills, default release flow, synced Hermes tuning

**169 canonical skills total** (167 + `workspace-organization` + `scratch-hygiene`), shipped to all
five provider trees. No new dependency, MCP server or pin change.

## Why these two skills exist

The pack already taught agents how to finish: verify, prove the artifact, converge CI. It did not
teach them where work should live, or what to do when the work is over. Both gaps produced the same
class of mess, and both are now defaults rather than habits:

- **`workspace-organization`** - when no workspace root exists, ask the user and offer candidates
  instead of silently creating projects under `C:\Users\<name>`; that directory is the operating
  system's home and lands in profile backups, roaming sync and cleanup sweeps. Keep source, build
  output and release scratch separate so "what is tracked", "what a cleanup may delete" and "what
  the next version folder contains" stay answerable. Maintain a `WORKSPACE.md` at the root: one
  table of projects, paths, build commands, version schemes and release targets, so the next session
  reads the map instead of re-walking the tree and re-paying for discovery.
- **`scratch-hygiene`** - one temp folder per task under the OS temp directory, never inside the
  repository, the workspace or the user profile; a script that proved reusable is promoted to
  `tools/` or the skill's `scripts/`, and everything else dies when the task does. Cleanup is part
  of done, and a version bump is the natural sweep point: the previous version's scratch, staging
  and superseded backups are exactly what must not survive into the next release.

## Default release flow, stated once

`release-checklist` now opens with the pack's canonical close-out: sync the live install
(`install_live_skills.py` when skills changed), sync the bundle, commit, push, converge CI on the
exact pushed SHA, tag, publish, verify the shipped bytes. A step that requires an application to be
closed - Hermes profile migration above all - is user-run by design: the exact command is printed,
the reason is stated, and it is never reported as applied from inside the running app. This matches
the migrator's own refusal while the Hermes desktop app is open; the refusal is a protection, not a
bug. `capability-profiles` carries the same rule next to the Hermes profile topology.

## Hermes tuning synced

The portable starter config now matches the maintainer's current choices: `agent.reasoning_effort:
max`, the free Ling 3.0 Flash VL summarizer at `ultra` reasoning with the 600-second timeout,
auto-routed vision whose ordered chain is the Flash vision model then ox-alpha, and the free
Nemotron Ultra pair added to the alias ladder. Deliberate divergences from the live machine are
kept and documented: explicit low-cost auxiliary pins for skills-hub/approval/MCP/curator/title
routing (auto-routing can choose paid models), the four-model free failover chain, and the 160k
compression cap with material-result pruning. These are portable safeguards, not machine state.
