# v8.13.0 — scoped reverse engineering and audited updates

The recommended start/resume templates are shorter and used once per chat,
not injected into every turn. Personal preferences, selected models, trust,
roleplay profiles and verified local skill overrides remain user-owned.
173 canonical skills across five provider trees; new guidance is on-demand
references, not additional skill-index entries.

## RE without global context bloat

`reverse-engineering` is a task recipe for all five providers. It selects
Universal Modder for game recon, an existing Reverse THIS! bench for specialist
tools, and optional REA 6.4.0 CLI for structured static-analysis evidence.
The pinned npm package's integrity, Windows help/static fixture and production
dependency audit were checked. No REA setup/update, full skill collection,
global MCP, target execution or native RE certification is implied.

The REA stdio probe advertises 170 tools / 1,954,683 compact UTF-8 schema bytes.
This is not a prompt, token bill or measured saving. CLI-first keeps that
inventory out of ordinary chats. CodeBurn's eight supplied recommendations
are classified in its on-demand reference rather than applied automatically.

## Scope of proof

- Hold Firecrawl instead of installing candidate 3.30.0: isolated production
  audits found high-severity dependencies in both it and the current pin.
  The suggested older fallback also has findings. The installer refuses held
  components even under explicit/extras selection; the doctor flags existing
  registrations without deleting personal configs. Native web and Playwright
  remain available. This is dependency evidence, not proof of exploitation.

Source/fixture gates, installed state, exact-SHA CI/security and release bytes
are separate checks. No paid inference, native RE engine, GPU/editor/gameplay
or universal quality/token-saving guarantee is asserted. Compatibility holds
remain explicit; latest alone is not a reason to overwrite a tested pin.
