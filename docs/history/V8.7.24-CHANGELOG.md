# v8.7.24 - version-proof public copy, enforced

**170 canonical skills total**, all five provider trees regenerated. No new dependency, no new MCP
server, no config change.

## The rule

Public copy splits by one question: can an agent edit it later?

- **Platform-locked pages** (Nexus Mods, Steam, itch, CurseForge, forum posts, store listings) are
  re-typed by hand in a web form. Nothing there can be fixed by the agent that notices the
  staleness, so it carries durable prose only: no version numbers, dates, counts, or "latest" in
  titles, summaries, description bodies, or alt text - and no version or date baked into hero
  images or thumbnails, because changing pixels costs a media re-upload.
- **Agent-editable surfaces** (GitHub README, CHANGELOG, docs, release bodies) may carry per-release
  facts; an edit there is one tool call.
- **Structured fields** (platform version field, changelog section) own the version number. One
  volatile fact gets one home: two places is one edit someone forgets, four is a page that
  contradicts itself.

Name the thing, not the build. "The installer ships a repair mode" stays true for ten releases;
"the 1.4.2 installer ships a repair mode" does not. A dependency version ("requires SKSE 2.2.6")
is still allowed - it names what the reader must install, not this project's own build.

## The enforcement

`_CANONICAL-SKILLS/public-copy-durability/` is the new canonical skill. Both presentation skills
now require it by name:

- `skyrim-nexus-publishing`: the page body stays version-proof, the version lives in the Nexus
  version field and the changelog section, and the hero/thumbnail must not bake in a version.
- `release-checklist` step 0 (public surface): locked pages carry no version numbers, dates or
  counts.

`test_public_copy_is_version_proof` pins the split, the concrete prohibitions and both
cross-references, so the rule cannot quietly disappear from a future edit.
