# v8.28.2 - shared Python PATH verification fix

Skill payload: 127 canonical skills, six provider trees.

An installer launched from an agent venv could inherit that venv's `python`
ahead of the persisted user PATH. The shared-Python check then resolved the
wrong interpreter, failed, and rolled the whole install back.

- `TOOLS/Set-SharedPython.ps1` now puts the chosen base interpreter first in
  the process PATH before verification, so the check and every child process
  see the shared Python even when the launching shell leads with a venv.
- `TESTS/Test-SharedPython.ps1` still passes, including the stale-binding,
  venv-refusal, Unicode-path and repeated-selection cases.
- This release was driven by a real local install failure; the same fix is
  what the next local install verification runs.
