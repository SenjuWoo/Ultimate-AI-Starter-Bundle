# v8.28.0 - reverse-engineering route and encyclopedia lookup

Skill payload: 127 canonical skills, six provider trees. Forge keeps its own
Skyrim pack.

The bundle had a tool-discovery pointer to Reverse THIS!, but no skill that
taught the route. This release adds one lean `reverse-engineering` skill and
folds the route discipline into the cross-game modding laws.

- `reverse-engineering` resolves the owner kit through
  `%LOCALAPPDATA%\ReverseThis\kit.json`, reads `sandbox/installed.json`, and
  calls only the shims it names. It documents the downstream-sink law
  (installation is not execution), module-scoped predicates with real resource
  budgets, and the hardware/provenance gate. It routes to reverse-this's own
  `AGENTS.md` and encyclopedia instead of duplicating them.
- `game-modding` and `references/MODDING-LAWS.md` require an
  encyclopedia/Context7 lookup before blind recon, the lowest viable route
  tier, `docs/CONTRACT.md` plus an offline harness before Tier 4-6, a
  three-role split for complex mods, and a post-mortem field-note and
  ERROR-REGISTRY sync at the ship gate.
- `TOOLS/discover_tools.ps1` now reports the Reverse THIS! root, bin,
  encyclopedia and both Ghidra endpoints. It stays read-only: the kit pointer
  is the source of truth, so no duplicate env copy goes stale.
- The Ghidra MCP endpoint is documented as `127.0.0.1:8081/mcp`; `8080` is the
  Ghidra-side HTTP server. Reverse THIS!'s own `encyclopedia/VALIDATION.md`
  corrects the draft's single `8080/mcp`, and this release follows it.
- Context7 indexing of `/senjuwoo/reverse-this` is owned by reverse-this. The
  skill falls back to `%ENCYCLOPEDIA_ROOT%` when the lookup returns "not found"
  rather than assuming the library exists.

Validation: canonical audit PASS (127 skills, no new budget warning), fanout
935 files per provider, release contracts and the full Windows pack gate run
before the release. Live game and GUI targets remain unexercised.
